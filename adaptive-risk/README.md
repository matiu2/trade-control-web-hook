# Adaptive prop-account risk protection

The `adaptive-risk` crate is broker independent and uses checked decimal arithmetic. `broker-ctrader/src/protection` connects it to the existing Open API and hybrid entry path. Ordinary accounts retain their existing behavior. No account is enrolled/enabled by this change, and no live submission is performed by the tools below.

## Controls and state

Default risk is 1% of the enrolled initial reference. Losing **completed setups** reduce it to 0.75%, 0.50%, 0.25%, then 0.10%. Drawdown supplies a separate ceiling at inclusive 2.5%, 3.5%, 4.5%, and 5% thresholds. The minimum of strategy request, worker/account cap, streak ceiling, drawdown ceiling, daily headroom, and account headroom determines volume. Fees, future swaps, slippage, fixed charges and overlap surcharges fit inside that allowance. Broker volume steps round down; minimum-volume failures reject.

The default internal daily/account stops are 2%/5%, separate from illustrative firm limits of 3%/6% and a 0.25% firm safety margin. These are example policies, **not verified The5ers terms**. The default reset is 17:00 America/New_York. Trading days are half-open UTC intervals with 23/25-hour DST days; ambiguous/nonexistent configured local boundaries reject.

Daily and account budgets use their own monetary floors. Open exposure uses current liquidation mark to stop, plus future/unreflected charges. Unrealised losses already in equity are not charged twice. Pending exposure uses remaining entry-to-stop volume. A crossed or invalid protective stop blocks new entries. All fragments sharing a request are summed; an unresolved reservation remains a conservative floor. No hedge or correlation credit is assumed. Configured overlap multipliers must be at least one.

`LossRule` can supply custom monetary thresholds. `StandardLossRule` supports static initial balance, trailing balance, and trailing equity. Trailing allowances are fixed to initial balance unless `trailing_allowance_tracks_reference` is explicitly enabled. This choice, and the firm's treatment of cash adjustments and peaks, must be checked against the purchased program. The cTrader adapter currently selects StandardLossRule; custom formulas require an explicit adapter implementation before enabling that program.

`RiskManager::begin` acquires an interprocess account lock. Hold the session across fresh reads, reconcile, authorize, refresh/revalidate and submit. A private account/policy-bound authorization cannot increase approved volume. Submission intent is fsynced before transport. Atomic state replacement and directory fsync preserve reservations, lockouts, references, policy, execution IDs, outcomes, counters and reconciliation watermarks. Missing/corrupt state never causes automatic enrollment. Each load requires reconciliation; policy content changes require explicit migration. Storage must be a durable local filesystem with working advisory locks and atomic rename, shared by every process trading that account. Do not run separate state directories or machines against one account.

New execution events invalidate earlier snapshots. Identical duplicate events are harmless; conflicting duplicates and late events for sealed setups suspend entries. Setup outcomes are sorted by `(closed_at, setup_id)` before rebuilding the streak, so simultaneous completions have stable attribution. Net losses increment it, wins reset by default, and break-even preserves it. Individual partial closes do not count as outcomes. A setup needs complete opening/closing volume for every position plus proof that all orders are terminal.

Daily lockouts latch until a verified new day successfully reconciles. Account lockouts latch indefinitely and need operator review/migration. Equity recovery restores the drawdown ceiling when no lockout has latched. Existing position closes, cancellations and stop tightening continue; there is no automatic liquidation. Protected stop widening is refused.

## cTrader enrollment and configuration

Copy [prop-risk-accounts.example.toml](prop-risk-accounts.example.toml) to the worker host's `~/.config/trade-control/prop-risk-accounts.toml`, or explicitly set `PROP_RISK_ACCOUNTS_FILE`. An explicitly configured missing file is an error. Only `enabled = true` profiles initially activate protection. Policies resolve by physical account ID and environment, so a second account alias cannot bypass them. Activation is sticky in `~/.local/state/trade-control/prop-risk-registry` (or the explicitly shared `PROP_RISK_REGISTRY_DIR`): missing/disabled policy files and state-directory changes then block instead of reverting to ordinary sizing, including after a restart. Removing protection requires an explicit operator migration. Keep this registry and the account state durable and shared across all processes. Duplicate enabled physical accounts or state directories in the profile file reject.

Before setting verification flags, check the current purchased program's rulebook: actual equity/balance references, intraday versus end-of-day peaks, reset zone and time, cash adjustments, thresholds, holding/financing rules, and whether fees are included. Verify cTrader fee signs and whether closing-detail commission includes opening charges against broker statements. Supply conservative account-currency cost estimates for each native instrument, including future swap exposure over the intended holding period; update them as broker costs change. Zero estimates mean a verified zero, not unavailable data. The loss/slippage estimates cannot bound failed stops, gaps or unlimited holding costs.

Enroll offline with verified boundary evidence, using a flat account before its first protected execution:

```sh
cargo run -p broker-ctrader --example prop-risk-admin -- \
  enroll /path/prop-risk-accounts.toml prop-account /path/day-reference.json
```

The JSON is `{"day":{"start":"2026-10-26T21:00:00Z","end":"2026-10-27T21:00:00Z"},"balance":"10000","equity":"10000"}` for that NY trading day. Match it to your actual enrollment date and firm reference; this example is not account evidence. Enrollment refuses to overwrite existing state.

On connection a read-only account monitor reconciles about once per second, subject to broker latency. Entry and monitor reads share the persistent gate. Every protected entry refreshes account/quote state again immediately before transport. Account-changing events during collection, event-stream loss, stale quote/conversion data, incomplete P&L position sets, missing stops, unresolved submissions and unsupported exposures prevent entry.

For static initial-balance/account and balance-based daily references, the bridge reconstructs the complete labelled deal/order history since `history_from`, verifies net executions against current balance and each closing-deal balance checkpoint exactly, and derives daily balances, balance peaks and historical realised stop breaches. Same-millisecond deal IDs use numeric ordering with broker balance checkpoints validating it. Recovered equity does not clear a historical stop breach. Outstanding executed inventory must exactly match broker position volumes. Equity and mark-to-stop exposure share one broker P&L sample; conservative conversion sides value stop losses and locked profits without mixing independent quote/P&L samples. A fee mismatch blocks rather than guessing net P&L. Cash adjustments, manual/unattributed trades, missing opening history, netted accounts, non-FX exposure or non-direct currency conversions require explicit reconciliation/support. The existing adapter remains limited to recognized spot FX unit contracts. A platform error without evidence of zero fills keeps its reservation; broker terminal history resolves rejected/cancelled requests. Typed NotSent errors and proven zero-fill market failures release their risk immediately. An ambiguous request with no broker history remains blocked until a broker-verified absence is explicitly supplied through fresh FirmEvidence.resolved_requests or the risk API. Never remove the state file to clear it.

Stable setup identity comes from the signed intent's `trade_id`, falling back to its intent ID, and is preserved through entry recovery paths. Each order keeps a separate idempotent request ID. All positions and pending requests bearing the same `risk:<setup_id>` label aggregate into one outcome, even across multiple orders. Missing or unsafe setup IDs block protected entries. Once the setup has no live members it is sealed; a later independent setup needs a new identity. Direct broker-library callers must supply EntryRequest.setup_id for protected accounts.

Daily equity/higher-of references and trailing-equity high-water marks **cannot** be reconstructed reliably from deal history. Those policies require `firm_evidence_file`, produced by an authoritative firm/broker reconciliation source. Static accounts also require this evidence after an unobserved interval exceeding the configured maximum data age when positions existed or opened in that interval: deal history cannot prove that floating equity never crossed a stop. It contains `account_id`, `environment`, `policy_version`, `day` (the DayReference above), `continuous_equity_high`, `observed_at`, `account_stop_breached`, `daily_stop_breached`, and optional `resolved_requests`. The stop flags must cover the configured internal stops, not merely the larger firm limits. Absence proofs must postdate their request reservation. Increment the policy version when changing the report source's rule interpretation. It must cover disconnection intervals and be fresh within the configured age. The bridge checks its identity, trading day, balance reference and monotonic peak; stop flags latch. No producer for a particular firm's report is assumed or enabled. These policies fail closed until that source exists and has been verified.

The adapter does not retrofit pre-enrollment positions or invent setup membership. Protected dry runs use the pure evaluation API; the existing broker dry-run entry rejects instead of persisting live reservations. Every protected live entry passes the manager in `entry::place_with_client_id`. FIX-only entries already refuse because they lack account/protection data. Raw standalone broker clients/manual terminal trades are outside this robot gate and must not be used to add risk to a protected account.

## Tests and observability

```sh
cargo test --manifest-path adaptive-risk/Cargo.toml --offline
cargo clippy --manifest-path adaptive-risk/Cargo.toml --all-targets --offline -- -D warnings
cargo fmt --manifest-path adaptive-risk/Cargo.toml --check
cargo test -p broker-ctrader
cargo clippy -p broker-ctrader --all-targets -- -D warnings
```

The pinned workspace has an existing missing `strategy-common/src/windows.rs` file and unavailable sibling path dependencies; see the implementation validation note in `reports/README.md`. No dependency repair is hidden in this feature.

Structured `tracing` events record decisions and policy limits without credentials. `metrics::snapshot` exposes current risk multiplier, streak, drawdown, daily loss/headroom, reserved exposure, blocked trades, circuit activations and accumulated/current reduced-risk duration for a metrics exporter. Counters/timing state persist. There is no required external metrics service.

## Replay and Monte Carlo

```sh
cargo run --release --manifest-path adaptive-risk/Cargo.toml --example compare -- replay records.json
cargo run --release --manifest-path adaptive-risk/Cargo.toml --example compare -- monte-carlo
cargo run --release --manifest-path adaptive-risk/Cargo.toml --example compare -- monte-carlo simulation-config.json records.json
```

Records are provenance-tagged: `{"dataset":"replay","trades":[{"at":"2026-01-05T22:05:00Z","net_r":"-1"},...]}`. `dataset` can also be `forward_test` or `live`; synthetic reports use `synthetic_provisional`. Supply actual chronological **net** R outcomes where available. Define net R as realised account-currency P&L (including actual fees, swaps and realised slippage) divided by the original nominal entry-to-stop risk of that setup. Unspent slippage reservations are not realised losses. No validated net-R journal was available in this checkout; the included report uses the requested provisional 58% / +2.13R / -1R model.

Replay compares fixed risk, streak only, drawdown only, and the combined policy with daily/account stops. All four use the same volume grid and configured slippage reserve when sizing; realised R multiplies approved nominal stop exposure. `average_risk_pct` reports that nominal exposure; `average_reserved_risk_pct` separately reports the larger all-in allowance. The default 1% budget therefore permits about 0.8333% nominal stop exposure with a 20% slippage reserve. Actual gap/slippage losses belong in net R; unspent reserve is never charged to P&L. Stops latch and count immediately after each outcome, including the last trade of a day or horizon. It retains actual timestamps and rejects nonchronological input. It models sequential, completed setups, not overlapping fills or intra-trade equity paths. Runs stop at the 10% default evaluation target or first firm account breach, or the record horizon. Reaching that target without any modeled firm breach is labelled "funded" only as a simulation proxy; real funding, minimum days, payout, leverage, consistency and other program rules are not modeled.

Monte Carlo uses seeded ChaCha8 and the same sampled path for all four comparisons. With records it uses fixed-length circular blocks of R outcomes: starts are uniform, a block wraps from the end to the beginning if needed, and block size may not exceed record count. This keeps endpoint sampling unbiased but introduces an explicitly synthetic last-to-first adjacency; without them it uses provisional binary returns. Both use an explicit `trades_per_day` distribution (default equally likely 1, 2 or 3), placing trades within timezone-aware trading days. Historical-block timing is replaced by this explicitly modeled distribution; adjust it to observed activity. Set `RISK_POLICY_FILE` to a standalone RiskPolicy TOML file to override the risk configuration. Reports embed that policy and all simulation inputs. Configure `simulations`, `trades`, `seed`, `trades_per_day`, `block_size`, `initial_balance`, `target_pct`, `start`, `win_probability`, `average_winner_r` and `average_loser_r` via JSON. The report command requires at least 10,000 runs per configuration. Reports include 95% normal mean confidence intervals and Wilson confidence intervals for target-success probability, conditional trades-to-target, net return, drawdown, streak, skips, risk, daily lockouts and firm breaches.

These are replay/model outputs, not predictions of live execution. Stops can slip or fail; internal limits cannot guarantee avoiding firm liquidation or a loss-limit breach.
